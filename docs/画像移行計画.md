## 目標フォルダ戦略

### 基本ルール

- **全画像は1記事に紐づく**
- 複数記事から参照が必要な場合は、同じ画像を記事ごとにアップロードする

### Cloudinary & ローカル `public/images/` の構成（ミラー）

```
public/images/
  {article-date}/
    {説明的なkebab-case名}.{ext}
```

Cloudinaryの公開ID形式:
```
blog/{article-date}/{filename（拡張子なし）}
```

例:

| ローカルパス | Cloudinary公開ID |
|-------------|-----------------|
| `public/images/2009-08-06/muramasa-screenshot-1.jpg` | `blog/2009-08-06/muramasa-screenshot-1` |
| `public/images/2003-12-31/okinawa-trip-1.jpg` | `blog/2003-12-31/okinawa-trip-1` |

## 移行フェーズ

### Phase 1: アップロードスクリプト改修

`scripts/upload-images.ts` をサブフォルダ対応に変更する。

**変更前**:
- `public/images/image.png` → 公開ID `blog/image`（フラット）

**変更後**:
- `public/images/2026-12-01/image.png` → 公開ID `blog/2026-12-01/image`（パス構造をそのまま使用）
- `public/images/` 配下を再帰スキャンするよう変更する

### Phase 2: 既存 `public/images/` の整理（27ファイル）

1. 各画像がどの記事に属するかを確認する
2. `public/images/{article-date}/` に移動し、必要に応じてリネームする
3. `npm run upload` を実行してCloudinaryにアップロードする
4. 記事内の既存Cloudinary URL（フラット形式）を新しいURL（年/記事別）に一括置換する

> 現在の参照数: 26か所（`src/content/posts/` 内）

### Phase 3: レガシー画像の移行（`public/legacy/gazou/prt/` → Cloudinary）

1. **未参照14ファイルの処置**を決める（目視確認後に削除 or 保存）
2. 参照ありの65ファイルを記事ごとに整理する:
   - 各画像を参照元記事を確認しながら `public/images/{article-date}/` に移動する
   - ファイル名を説明的なkebab-caseに改名する（例: `muramasa1.jpg` → `muramasa-wii-screenshot-1.jpg`）
3. `npm run upload` を実行する
4. 記事内の `/legacy/gazou/prt/xxx.jpg` パスを新しいCloudinary URLに一括置換する
5. `public/legacy/` ディレクトリをGitから削除する

> 現在の参照数: 65か所（2003〜2012年の記事が中心）

### Phase 4: クリーンアップ

- `npm run build` でビルド確認
- `docs/仕様.md` の「画像管理」セクションを更新する

## 作業の進め方

Phase 3の旧サイト画像のリネームは記事の文脈を見ながら進める必要があるため、記事単位で少しずつ進める。

推奨の実施順:
1. Phase 1（スクリプト改修）を実装・動作確認する
2. Phase 2（既存 `public/images/` 整理）を実施する
3. Phase 3（レガシー画像）を記事ごとに少しずつ進める
4. Phase 4（クリーンアップ）で完了とする
